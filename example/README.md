# dowel example

A minimal Flutter consumer app that wires `dowel` as its CLI dispatcher.

This example was generated by `dart run dowel install` and represents the canonical shape every Flutter app takes when it adopts dowel: a tiny `bin/dispatcher.dart` wrapper, a `lib/app/` codegen barrel surface, and an in-workspace plugin under `packages/awesome_plugin/`.

## What lives where

- `bin/dispatcher.dart` — the consumer wrapper. Imports `dowel`, registers consumer commands from `lib/app/commands/_index.g.dart`, expands plugin providers from `lib/app/_plugins.g.dart`, then calls `runDowel(args)`.
- `lib/app/commands/_index.g.dart` — codegen barrel. Regenerated by `make:command` and `commands:refresh`. Lists every consumer command class.
- `lib/app/_plugins.g.dart` — codegen barrel. Regenerated by `plugin:install <name>` and `plugins:refresh`. Lists every registered plugin provider.
- `packages/awesome_plugin/` — a workspace-resolved sample plugin scaffolded by `make:plugin awesome_plugin`. Demonstrates the `DowelServiceProvider` contract and the `install.yaml` schema.

## Try it

From this directory:

```bash
flutter pub get
dart run dowel list           # show every registered command
dart run dowel doctor         # validate environment
dart run dowel start          # run the Flutter app under dowel supervision
```

To exercise the MCP server (stdio JSON-RPC):

```bash
dart run dowel:mcp
```

The full surface (10 substrate tools + per-plugin tools, idempotent installer DSL, scaffolders) is documented at [anilcancakir.com/dowel](https://anilcancakir.com/dowel).

## Note on the archive

This `example/` ships with the pub.dev package archive trimmed: only `lib/`, `bin/`, `packages/awesome_plugin/lib/`, `pubspec.yaml`, and this README. The full Flutter platform scaffold (`android/`, `ios/`, `macos/`, `linux/`, `windows/`, `web/`) is excluded by `.pubignore` to keep the archive under 500 KB. Clone the GitHub repository for a runnable end-to-end example.
